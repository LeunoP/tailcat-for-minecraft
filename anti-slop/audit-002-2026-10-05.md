# Tailcat 1.20.1, 1.21.1, 26.2, 26.3 메뉴 배치 감사

- 모드: DURING, 세션 지정
- 범위: 1.21.11을 제외한 Fabric, Forge, NeoForge 멀티플레이 화면 Tailcat 연결 버튼
- 방식: 코드 정적 검토
- 실행 검증: 수정 전 인게임 화면 크기 변경 재현은 하지 않았습니다.
- 코드 변경: 이 감사 시점에는 하지 않았습니다.

## Findings

### 3. [HIGH] 재사용되는 연결 버튼의 현재 화면 배치가 갱신되지 않습니다

- 규칙: R-03 반응형 레이아웃, R-26 동작 가능한 인터랙션
- 위치: `mod-fabric-1.20.1`, `mod-forge-1.20.1`, `mod-neoforge-1.20.1`, `mod-fabric-1.21.1`, `mod-forge-1.21.1`, `mod-neoforge-1.21.1`의 `McLinkClient.java` 연결 버튼 초기화 함수
- 근거: 기존 `mclink.join` 버튼을 찾으면 즉시 반환합니다. 화면 재초기화 시 기존 버튼이 남는 경우 새 너비·높이의 목표 좌표와 서버 목록 영역을 다시 계산하지 않습니다.
- 영향: 창 크기 변경 또는 재초기화 후 연결 버튼이 예전 좌표에 남거나, 화면 목록과 버튼 배치가 서로 맞지 않을 수 있습니다.
- 개선 방향: 각 초기화에서 현재 바닐라 버튼 좌표를 기준으로 행을 다시 확보하고, 기존 버튼에도 현재 화면 크기 기준의 위치와 폭을 적용하십시오.

### 4. [HIGH] 26.2 및 26.3의 레이아웃 재배치가 기존 버튼 경로에서 생략됩니다

- 규칙: R-03 반응형 레이아웃, R-26 동작 가능한 인터랙션
- 위치: Fabric, Forge, NeoForge의 `mod-*-26.2/src/main/java/com/tailscale/mclink/McLinkClient.java` 및 `mod-*-26.3/src/main/java/com/tailscale/mclink/McLinkClient.java` 연결 버튼 초기화 함수
- 근거: 기존 `mclink.join` 버튼을 찾으면 반환하므로 현재 너비에 맞춘 폭 적용, `HeaderAndFooterLayout` 재배치, 서버 목록 크기 갱신을 건너뜁니다. 레이아웃 대체 경로도 기존 버튼을 재배치하지 않습니다.
- 영향: 화면 재초기화 때 Tailcat 행과 서버 목록의 배치가 현재 창 크기와 불일치할 수 있습니다.
- 개선 방향: 기존 버튼은 중복 추가하지 않되 폭과 레이아웃은 매 초기화 때 갱신하고, 목록 크기도 다시 계산하십시오.

### 5. [HIGH] 연결 버튼 폭이 화면 폭에 맞게 제한되지 않습니다

- 규칙: R-03 반응형 레이아웃
- 위치: 위 12개 대상 모듈의 `McLinkClient.java` 연결 버튼 생성 코드
- 근거: 기존 레이아웃은 204px, 새 `HeaderAndFooterLayout`은 308px의 고정 폭을 사용하며 화면 폭에 대한 상한이 없습니다.
- 영향: 게임 GUI의 가용 너비가 버튼 폭보다 작아지면 버튼이 화면 가장자리에 붙거나 일부가 잘릴 수 있습니다.
- 개선 방향: 기존 버튼과 새 버튼 모두 현재 화면 폭에서 좌우 여백을 남길 수 있는 폭으로 제한한 뒤 중앙 또는 바닐라 레이아웃에 맞춰 배치하십시오.

## 수정 및 검증 결과

- Findings 3-5를 1.20.1, 1.21.1, 26.2, 26.3의 Fabric, Forge, NeoForge 총 12개 모듈에 반영했습니다.
- 화면 초기화마다 현재 크기에 따라 연결 버튼 위치와 폭을 갱신합니다. 자동 푸터 레이아웃이 있는 버전은 푸터를 다시 정렬하고 서버 목록 크기도 갱신합니다.
- 12개 모듈의 `compileJava`가 모두 통과했습니다. Forge 및 NeoForge 1.20.1에서 기존 `FMLJavaModLoadingContext.get()` 사용에 대한 폐기 예정 경고가 출력됐지만 컴파일 실패는 아닙니다.
- `git diff --check`가 통과했습니다. Git의 CRLF 변환 알림만 출력됐습니다.
- 인게임 창 크기 변경 재현은 실행하지 않았습니다.
