# Tailcat 추가 기능 개발 계획

작성일: 2026-10-09

대상: Fabric, Forge, NeoForge의 1.20.1·1.21.1·1.21.11·26.2·26.3 모듈과 Paper 플러그인.

목표는 접속 문제를 사용자가 직접 파악하고 복구할 수 있게 하고, 호스트가 공유 세션을 게임 안에서 관리할 수 있게 하는 것입니다. 아래는 계획과 완료 기준이며, 실제 구현·검증 상태는 다음 진행 기록을 기준으로 확인합니다.

## 구현 진행 (2026-10-09)

준비 단계의 세션 격리·실패 정리·비동기 헬퍼 시작/종료, 공통 Java 17 계약 테스트, 전체 빌드 목록과 격리된 Prism 시작 점검 실행기를 반영했습니다. 세 로더의 다섯 버전과 Paper에 같은 공통 로직을 사용합니다. 상세 변경 및 검증 범위는 `docs/PREPARATION_IMPLEMENTATION.md`에 기록합니다.

준비 단계에서 공통 Java 21개, Python 15개 및 16개 대상 빌드/JAR 검사가 통과했습니다. 이후 첫 기능 묶음과 호스트 화면 개선을 반영하여 현재 공통 Java 40개와 Python 22개가 통과했으며, 전체 16개 대상 빌드·검사 및 dist 갱신을 완료했습니다. 빌드 ID는 `20261009T082015Z`입니다. 진단 저장은 개발자 API 전용으로 변경했으며 일반 배포의 버튼·명령은 제거했습니다. 접속자 대기 표시, 현재/다음 공유 정원 구분, 호스트 설정의 실행 내 보관과 기존 LAN 유지 안내도 반영했습니다. 결과와 인게임 검증 범위는 `docs/FEATURE_IMPLEMENTATION.md`에 기록합니다.

1~3번의 연결 진단·파일 저장, LAN 공개 상태 복원, 서버 운영 명령·설정을 15개 모드와 Paper에 구현했습니다. 4번의 성공한 코드·중계 옵션을 이번 실행에서만 보관하는 부분도 반영했습니다. 자동 재접속, 신규 접속 잠금·만료 예약, 초대 재발급은 아직 구현하지 않았습니다.

헬퍼 두 개를 동시에 중계 연결하여 TCP 왕복 통신, 구조화된 경로·상태 조회 지연, TCP 자원 한도 초과, 백엔드 중지 안내와 EOF 종료를 검증했습니다. 기존 중계 전용 환경변수가 초기 핸드셰이크를 막는 현상과 Tailcat 상태 함수가 피어 정보를 누락하는 문제도 저장소 내 고정 소스 보정으로 해결했습니다. 격리된 Fabric 1.21.11에서 초대 오류·진단 저장·뒤로가기·64명 설정 공유 시작·종료와 일시정지 재개 로그를 확인했습니다. 실제 Minecraft 두 클라이언트 접속, 월드 시간 비교, 작은 화면·컨트롤러 조작, Linux/Deck 실행 및 설치 경로 배포는 아직 확인하지 않았습니다. 따라서 첫 기능 묶음의 완료 기준 전체가 통과한 상태는 아닙니다.

Forge 1.21.11 빌드는 기존에 수정된 ForgeGradle 6.0.54 캐시를 사용합니다. 현재 환경에서의 전체 빌드 통과와 별도로, 깨끗한 환경의 재현성 확인 및 저장소 안에서 관리하는 우회 처리의 정리가 필요합니다.

## ESC 참가자 연결 상태 추가 작업 (2026-10-11)

ESC 참가자 연결 상태를 점수판에서 `mclink:connection_status` 직접 페이로드 방식으로 전환했습니다. 호스트 서버가 활성 Tailcat 경로를 플레이어 소켓 주소와 매칭하고, 플레이어 이름과 직접·중계·확인 불가·Tailcat 미사용 코드만 스냅샷으로 전송합니다. IP, 초대 코드, 중계 서버명은 포함하지 않습니다. 화면의 스크롤 동작은 유지합니다. 모드와 Paper의 상태 명령어도 플레이어별 P2P·DERP 경로를 표시합니다. 16개 지원 대상 전체 빌드와 공통 계약 검증을 통과한 산출물을 `dist`에 갱신했습니다. 실제 다중 클라이언트 수신과 운영 서버 출력 검증은 별도입니다. 상세 구현은 `docs/FEATURE_IMPLEMENTATION.md`의 “ESC 참가자 연결 상태”를 참고합니다.

## 연결정보 화면 개선 구현 (2026-10-11)

호스트 공유 화면의 참가자 목록을 제거하고 `연결정보` 버튼으로 참가자와 동일한 화면을 엽니다. 내 연결 상태·핑 고정, 본인 표시, P2P·DERP 용어 통일, 목록 스크롤바와 페이지 단위 이동을 적용합니다. 연결 기준 설명과 공유 종료·서버 종류 구분 안내는 추가하지 않습니다.

호스트가 전송하는 상태 규격을 버전 2로 확장해 플레이어별 Minecraft 핑(ms)을 포함했습니다. 버전 1을 수신하면 핑은 측정 불가로 처리합니다. 마지막 정상 스냅샷 수신 후 60초가 지나면 연결 끊김과 핑 측정 불가를 표시하고, 새 스냅샷 수신 시 복구합니다. 게임 연결은 강제로 종료하지 않습니다.

호스트 정원의 64명 상한과 연결정보 목록의 64명 잘림을 제거했습니다. Minecraft 정원 필드의 정수 표현 범위에서 설정할 수 있고, 호스트를 포함하는 규칙은 유지합니다. 큰 참가자 목록은 기존 메시지 크기 한도 안에서 분할 전송하고, 모든 조각을 받은 경우에만 새 목록과 수신 시각을 반영합니다. 100명·1,000명 정원과 1,000명 목록 복원, 분할 메시지 누락·혼합·만료, 60초 경계·복구 공통 검증은 통과했습니다. 화면 변경을 15개 모드에 적용했으며 공통 Java 58개·Python 25개 검사와 전체 16개 빌드를 통과했습니다. `20261010T233549Z` 산출물을 dist에 갱신하고 해시를 대조했습니다. 실제 인게임 화면과 대규모 동시 접속 검증은 별도입니다.

## 1. 연결 진단과 진단 파일 저장

사용자 화면에 헬퍼 준비, 중계 준비, 원격 터널 연결, Minecraft 접속을 단계별로 표시합니다. 현재 join의 ready는 로컬 리스너 준비 시점이므로, 실제 서버 접속 성공과 별도로 표현합니다.

실패는 잘못된 코드, 중계 준비 실패, Minecraft 서버 연결 실패, 정원 초과, 헬퍼 종료, 시간 초과로 구분합니다. 오류마다 다시 시도, 코드 확인, 호스트 상태 확인 등 실행 가능한 안내를 제공합니다.

연결 방식은 헬퍼가 제공하는 구조화된 상태를 우선 사용합니다. 직접 연결이 실패해 중계로 돌아가는 경우에도 표시를 갱신하고, 측정하지 못한 정보는 '확인 중' 또는 '알 수 없음'으로 표시합니다. Minecraft 핑과 별도로 측정한 터널 지연에는 각각 이름을 붙입니다. 접속자별 경로 표시는 실제로 얻을 수 있는 API 범위를 먼저 검증합니다.

진단 파일에는 모드·헬퍼·로더 버전, 플랫폼, 접속 단계, 오류 코드와 제한된 분량의 최근 로그를 담습니다. 초대 토큰은 제외합니다. 진단 내보내기는 개발자 API로만 유지하며 일반 배포의 버튼과 diagnose 명령은 제공하지 않습니다. API를 명시적으로 호출한 경우에만 로컬에 저장합니다.

완료 기준:

- 잘못된 초대, 중계 준비 실패, 백엔드 서버 중지, 시간 초과를 재현해 각각 다른 원인과 안내가 나옵니다.
- 직접 연결에서 중계로 전환될 때 표시가 실제 경로를 따라 바뀝니다.
- 지역을 모르면 임의의 지역명이 나오지 않습니다.
- 진단 파일에서 초대 토큰이 노출되지 않습니다.
- 돌아가기·취소 후 늦게 도착한 이전 접속 결과가 새 세션이나 화면을 바꾸지 않습니다.

## 2. 공유 종료 후 월드 상태 복원

공유 시작 전에 LAN 공개 여부, 정원, 인증 설정을 기록하고 Tailcat이 변경한 자원을 추적합니다. 공유 종료 시 게스트에게 종료 이유를 전달하고 터널, Tailcat이 연 LAN 리스너와 광고를 정리한 뒤 이전 상태로 복원합니다. 사용자가 미리 LAN으로 연 월드는 기록된 기존 LAN 상태를 유지합니다.

Minecraft 버전별로 공개 상태와 일시정지 조건을 되돌릴 수 있는지 먼저 작은 구현으로 검증합니다. 해당 검증이 통과한 뒤 15개 모듈에 적용합니다.

완료 기준:

- 일반 싱글플레이에서 공유 시작 후 종료하면 일시정지 중 게임 시간이 멈춥니다.
- 같은 월드에서 공유 시작·종료를 반복해도 포트와 헬퍼가 누적되지 않습니다.
- 미리 LAN으로 연 월드는 Tailcat 종료 후에도 이전 LAN 상태가 유지됩니다.
- 접속 중인 게스트에게 종료 이유가 전달되고 정원·인증 설정이 복원됩니다.

## 3. Paper/전용 서버 운영 명령과 설정

관리자 명령으로 `/tailcat start`, `/tailcat stop`, `/tailcat restart`를 제공합니다. 기존 invite/status 명령과 같은 권한 기준을 사용하며, 일반 플레이어는 본인 상태를 확인할 수 있습니다. 진단 저장은 개발자 API로만 제공합니다.

설정 항목은 자동 공유 여부, 중계 전용, 접속 한도, 시작 시간 제한, 언어로 시작합니다. Paper의 현재 자동 공유 기본 동작을 유지하고 설정으로 선택할 수 있게 합니다. 설정값이 유효하지 않으면 적용할 값과 수정 방법을 안내합니다. 실행 중 적용 가능한 설정과 터널 재시작이 필요한 설정을 구분합니다.

정원 계산은 서버 유형에 맞춥니다. 싱글플레이 정원에는 호스트가 포함되어 원격 게스트 한도는 지정 정원에서 1명을 뺀 값입니다. 64명 상한은 두지 않습니다. 전용 서버에는 별도 로컬 호스트 자리가 없으므로 서버의 max-players와 설정값을 기준으로 원격 접속 한도를 계산합니다. TCP 연결 수와 로그인한 플레이어 수를 구분해 서버 조회 연결을 플레이어 정원으로 오인하지 않도록 설계합니다.

완료 기준:

- 서버를 재부팅하지 않고 시작·중지·재시작이 가능하고 중복 헬퍼가 실행되지 않습니다.
- 터널 중지·실패 시 초대 상태와 파일이 실제 세션을 반영합니다.
- 일반 플레이어에게 운영 명령과 전체 연결 정보가 제공되지 않습니다.
- Paper와 세 로더 전용 서버에서 설정의 의미가 일치합니다.

## 4. 직전 성공 코드와 재접속

Minecraft 접속 성공이 확인된 코드와 중계 옵션을 이번 실행의 메모리에 보관합니다. 게임을 다시 시작하면 직전 코드 접속은 비활성화됩니다.

연결이 끊겼을 때 오류 화면에 재접속 버튼을 제공합니다. 자동 재접속은 선택 설정으로 제공하며 첫 안은 1·3·5초 간격으로 최대 3회 시도하는 방식입니다. 사용자가 취소하거나 서버가 퇴장·차단·인증 실패·버전 불일치를 알리면 해당 시도를 종료합니다. 헬퍼 재생성과 Minecraft 재접속은 하나의 시도 ID로 묶습니다.

완료 기준:

- 실패한 코드로 성공했던 직전 코드를 덮어쓰지 않습니다.
- 재실행 후 이전 코드를 사용할 수 없습니다.
- 취소 후 재접속이 다시 시작되지 않습니다.
- 호스트 중지와 Wi-Fi 일시 끊김을 구분해 안내합니다.
- Steam Deck 절전 복귀 상황에서도 중복 연결과 남은 헬퍼가 발생하지 않습니다.

## 5. 신규 접속 잠금과 만료 예약

호스트 화면과 서버 관리자 명령에 신규 접속 허용·잠금을 추가합니다. 잠금 후 기존 플레이어는 계속 플레이하고 새로운 접속과 재접속은 거절합니다. '15분 뒤 신규 접속 잠금'과 같은 예약을 제공하고 호스트에게 남은 시간을 표시합니다.

잠금과 시간 제한은 호스트 헬퍼의 접속 수락 지점에서 적용합니다. 클라이언트 화면이나 초대 문자열에만 만료 표시를 넣어 접속을 제한한 것처럼 보이는 구현은 사용하지 않습니다. 구형 클라이언트도 호스트의 접속 제한을 받으며, 상세 거절 이유의 전달 방식은 프로토콜 확장 단계에서 정합니다.

완료 기준:

- 잠금 중 신규 접속은 거절되고 기존 게스트는 연결을 유지합니다.
- 잠금 해제 후 새 접속이 다시 가능합니다.
- 만료 예약과 수동 잠금이 일관된 호스트 상태를 표시합니다.
- 중계 전용·직접 연결 모두 같은 접속 정책을 적용합니다.

## 6. 초대 코드 재발급

현재 초대에는 서버 공개 키에 기반한 Tailcat 토큰이 들어 있습니다. 표시 문자열만 바꾸면 기존 토큰을 사용할 수 있으므로, 재발급 시 서버 키와 터널 세션을 교체해 이전 코드가 실제로 연결되지 않도록 합니다.

첫 구현은 재발급 시 기존 게스트도 다시 접속하는 동작으로 설계하고 실행 전에 그 영향을 표시합니다. 기존 게스트를 유지하는 재발급은 이전 서버의 신규 접속을 차단하면서 기존 연결을 유지할 수 있는지 검증한 후 후속 기능으로 다룹니다. 1회성·개별 초대는 플레이어 인증과 서버 조회 연결을 구분하는 설계 이후에 추가합니다.

완료 기준:

- 재발급 후 이전 코드로 접속할 수 없고 새 코드로 접속할 수 있습니다.
- 재발급 실패 시 호스트에 유효한 초대 상태와 연결 상태가 명확하게 표시됩니다.
- invite 파일과 게임 내 복사 코드가 같은 세션의 코드를 가리킵니다.

## 후속 편의 기능

- 월드별 공유 설정: 인원수와 중계 전용 옵션을 기억합니다. 직전 접속 코드의 실행 한정 정책은 그대로 유지합니다.
- 접속 전 점검: 헬퍼 실행 가능 여부, 초대 형식, 로컬 대상 포트, 중계 준비를 점검하고 실패 지점을 안내합니다.
- 플레이어별 퇴장: 이미 있는 접속자 목록에서 특정 플레이어를 퇴장시키고, 재접속 허용 여부를 명확하게 구분합니다. 식별은 Minecraft UUID와 실제 터널 연결 정보를 기준으로 합니다.
- 호스트 정보 미리보기·정원 대기: 호스트 버전·필수 모드 정보를 확인하거나 빈자리를 기다리는 기능은 서버와 클라이언트 사이의 추가 통신을 검증한 후 별도 계획으로 구체화합니다.

### 추가 완료 기준

- 세션 A 시작→취소→세션 B 시작 후 A의 ready/error/exit/log 이벤트를 늦게 전달해도 B의 화면과 연결이 유지됩니다.
- Paper와 모드 전용 서버에서 시간 초과·헬퍼 강제 종료·잘못된 JSON을 재현한 뒤 초대 코드가 무효화되고 관리자 재시작이 가능합니다. 종료한 세션이 초대 파일을 다시 생성하지 않습니다.
- 느린 헬퍼 추출·시작·종료를 재현해도 게임 메인 스레드는 종료 대기를 하지 않고 취소 동작을 처리합니다.
- 1280×800 Steam Deck, 작은 창, 여러 GUI 배율과 긴 한국어·영어·일본어 오류 메시지에서 입력창·설명·버튼·목록이 겹치지 않습니다. 키보드와 Controlify로 전체 작업 흐름을 수행할 수 있습니다.
- Deck에 배포한 1.20.4 및 1.21.3·1.21.4·1.21.5·1.21.8·1.21.10 인스턴스는 범위 메타데이터만을 근거로 호환 완료 처리하지 않고 실제 실행·공유·접속 결과를 기록합니다. 지원 범위 조정은 해당 결과를 근거로 합니다.
- 전체 빌드 대상은 15개 모드와 Paper 총 16개이며, 릴리스 목록의 각 항목이 실제 JAR 메타데이터·클래스 Java 버전·내장 헬퍼 해시와 일치합니다. Paper의 plugin.yml 버전 필드도 검사합니다.
- 테스트를 시작·실패·취소해도 다른 게임이나 Gradle 프로세스가 종료되지 않고 이전 로그가 보존됩니다. 단순 리소스 로딩 메시지만으로 접속 성공을 판정하지 않습니다.
- 플레이어 정원 검증은 Minecraft 로그인 완료 인원을 기준으로 하며 TCP 상태 조회와 추가 연결의 자원 한도는 별도로 검사합니다. 정원에 호스트를 포함하되 64명 상한은 두지 않습니다.

## 공통 구현 기반과 검증

헬퍼 이벤트와 상태 모델은 화면·매핑 API를 제외한 공통 Java 코드로 분리합니다. 최소 지원 환경인 Java 17을 기준으로 하며 버전별 화면과 Minecraft 서버 조작은 각 모듈의 어댑터에서 처리합니다.

현재 HelperEvent는 알 수 없는 필드와 이벤트를 거절합니다. 새 프로토콜은 버전·기능 협상을 정의하고, 이전 호출 방식에는 기존 ready/error/stopped 형식을 유지합니다. 새 이벤트를 내보내기 전에 15개 모듈과 Paper의 수신부를 함께 준비합니다. stdin EOF로 종료하는 현재 동작도 유지하면서 운영 명령을 읽을 수 있게 확장합니다.

헬퍼 연결 이벤트에는 연결 ID와 백엔드 소켓 정보를 포함하는 방식을 검증합니다. Minecraft 서버에서 보이는 원격 소켓과 대응시켜 Tailcat 접속자를 식별하며, 루프백 IP만으로 판정하는 현재 방식의 한계를 줄입니다. 경로·지연 정보를 얻는 API는 실제 사용 중인 Tailcat 의존성 버전에서 확인합니다.

검증은 기능 단위의 Go·Java 프로토콜/상태 테스트와 실제 두 클라이언트 접속으로 진행합니다. 새 기능에 의미 있는 성공·실패·취소·늦은 이벤트 시나리오를 포함하고, 15개 모드와 Paper 빌드를 통과시킵니다. 로더·버전 조합별 시작·공유·접속·뒤로가기·종료 동작을 확인하고 Windows와 Linux/Steam Deck에서 직접/중계 연결을 확인합니다.

배포 JAR에는 같은 소스에서 만든 헬퍼와 일치하는 체크섬을 넣습니다. 완료된 묶음별로 dist를 갱신하고 해당 플랫폼에 배포합니다. Paper 서버 설치는 서버의 plugins 디렉터리를 대상으로 진행합니다.
